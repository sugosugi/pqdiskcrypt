# pqdiskcrypt

本地文件加密桌面工具，支持口令保护与后量子混合公钥保护。

`pqdiskcrypt` 用于加密移动硬盘、U 盘或指定文件夹中的文件，提供图形界面、逐文件流式加解密、可选的文件名隐藏和卷密钥管理。加解密在本机完成，正常运行不需要网络或服务器。

当前版本：`5.4.4`。

这是 Python 源码包。已有可用运行环境时，用包内 `pqdiskcrypt.py` 替换程序目录中的同名文件即可；原有 `.pqvolume` / `.pqfc` / `.pqdir` 格式保持兼容。不要把程序包解压到正在处理的加密卷内。

> **重要：这是文件级加密工具，不是扇区级全盘加密，也不能替代数据备份。处理真实数据前，请备份数据、卷头和私钥，并先在副本上完成一次加密与解密。项目尚未经过独立安全审计。**

## 主要功能

- **文件夹与硬盘目录加密**：扫描指定目录，逐文件处理；卷模式按 64 KiB 分块读写，大文件无需整体载入内存。
- **口令保护**：使用 Argon2id 派生密钥，保护卷主密钥或单文件密文。
- **混合公钥保护**：结合 X25519 与 ML-KEM-1024，支持通过对应私钥解锁。
- **认证加密**：使用 AES-256-GCM，校验密文完整性；各卷文件使用独立派生的文件密钥，并带有密钥承诺。
- **可选的文件名隐藏**：将文件和目录改为随机 ID，原名称保存在加密目录清单中。
- **卷管理**：增删口令槽、公钥槽，备份或恢复卷头，切换文件名隐藏状态。
- **单文件模式**：支持口令、公钥以及带 ML-DSA-87 发件人签名的加密文件。
- **本地诊断**：检查目录中的文件类型，查找被改名的密文，按需导出诊断报告。

**多个密钥槽是不同的解锁入口，任意一个有效入口即可解锁，不是双因素认证。**

## 安全机制

| 范围 | 处理方式 |
| --- | --- |
| 后量子后端 | 默认使用 `pqcrypto / PQClean` 原生实现；缺少原生库时拒绝启动，不静默退回纯 Python 运算 |
| 密钥导入 | 检查规范编码、公私钥一致性、密钥哈希和签名匹配，而不仅检查长度 |
| 路径与清单 | 拒绝路径穿越、绝对路径、Windows 设备名、备用数据流和不安全的清单条目 |
| 文件类型 | 在关键访问路径检查符号链接、联接点、重解析点、硬链接和特殊文件 |
| 输入与资源 | 限制 JSON 大小、嵌套深度、槽数量和 KDF 计算预算，拒绝重复字段和非有限数 |
| 临时文件 | 独占创建；POSIX 使用 `0600`，Windows 创建时设置仅当前用户和 SYSTEM 可访问的受保护 DACL |
| 写入与校验 | 不忽略刷盘错误；删除原件的加密操作强制重读认证，并比较内容哈希 |
| 冲突与并发 | 不自动覆盖已有明文或密文，使用跨进程卷锁，并检查源文件是否发生变化 |
| 中断恢复 | 不自动删除未知 `.pqdisk.tmp.*`，避免误删可能有恢复价值的残留 |
| 日志隐私 | 默认不写磁盘日志；诊断报告由用户选择位置导出 |
| 依赖 | 固定运行依赖版本，以 `requirements.lock` 校验发布包 SHA-256 |

## 环境与安装

### 环境要求

- 源码运行或打包需要 Python，以及 tkinter 图形界面组件。
- 以下 Windows 步骤以官方 64 位 CPython 3.12 / 3.13 为目标环境。
- 本次源码测试环境为 Windows x64、CPython 3.12.14；没有完成 macOS、Linux 或所有文件系统的实机验证。
- 源码安装和构建通常需要联网下载依赖；应用正常加解密不需要联网。
- 磁盘应预留至少容纳一个最大文件输出及其额外开销的空间。保留原文件时，还需为所有加密副本预留空间。

锁定的主要运行依赖：

| 依赖 | 版本 |
| --- | --- |
| cryptography | 50.0.1 |
| pqcrypto | 0.4.0 |
| cffi | 2.0.0 |
| pycparser | 2.23 |

较旧 Python 所需的类型扩展依赖也已按环境条件锁定。完整约束以 `requirements.txt` 和 `requirements.lock` 为准。

### Windows 源码运行

解压源码包，在**同时包含 `pqdiskcrypt.py` 和 `requirements.lock` 的目录**打开 PowerShell。逐步执行；某一步报错时先处理错误，不要跳过继续。

1. 创建独立虚拟环境并安装已锁定的运行依赖。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes --only-binary=:all: -r requirements.lock
```

2. 运行启动自检。

```powershell
.\.venv\Scripts\python.exe pqdiskcrypt.py --selftest
```

3. 自检通过后启动图形界面。

```powershell
.\.venv\Scripts\python.exe pqdiskcrypt.py
```

如果系统使用 `py` 启动器，可以用 `py -3.12 -m venv .venv` 替换第一条命令。无须激活虚拟环境，也无须修改 PowerShell 执行策略。

macOS / Linux 可将上述虚拟环境解释器路径替换为 `.venv/bin/python`；还需确保对应平台具备 tkinter 和依赖 wheel。相关平台分支仍需自行验证。

`--require-hashes` 用于校验依赖产物，`--only-binary=:all:` 限制安装 wheel。没有匹配平台的 wheel 时安装会停止；请先检查平台和 Python 版本，不要随意取消校验或更换不可信下载源。

## 使用方法

### 1. 准备密钥与备份

口令模式不需要先生成公钥。使用公钥模式时，在“密钥”页生成密钥对，并分别保存：

- `.pub`：用于加密，可提供给预期发送方；使用前通过可信渠道核对公钥指纹。
- `.key`：用于解锁，默认使用口令保护。妥善备份，不要公开或与密文一起随意分享。

卷头、私钥和数据备份应放在独立位置。**不要将卷头备份或唯一的私钥副本放在即将被处理的目录内。**

### 2. 加密文件夹或硬盘目录

1. 打开“加密硬盘”页，选择移动硬盘、U 盘根目录或待处理的文件夹。
2. 检查扫描结果，确认没有选错目录。
3. 设置口令槽、公钥槽，以及是否隐藏文件名、是否保留原文件。
4. 确认开始；首次加密时手动选择卷头保存位置，建议保存在本卷之外。若取消保存，则不开始加密。
5. 等待处理完成，检查失败、跳过和警告项目。

删除原件的加密流程会先写出临时密文，刷盘，再重读认证并校验内容，成功提交后才尝试删除原件。若原件只读或删除失败，可能同时保留原件和加密副本；需要核对结果后处理。

再次运行会重新扫描，将新增文件并入现有卷。内容相同的明文与密文会在完整认证和哈希比对后复用；无需手动移走试运行时保留的原文件。**已有同名密文不会被不同内容的新版本自动覆盖**；遇到不同版本请妥善保留旧版本，再为新文件改名或处理冲突。

### 3. 解密

1. 打开“解密硬盘”页，选择对应卷的根目录。
2. 自动识别本地唯一可用卷头，或手动载入之前保存的外部卷头，再使用有效口令或私钥解锁。
3. 开始还原，完成后核对文件数量、内容和警告。

同名明文已经存在时，程序会跳过，不覆盖现有文件，并保留相关密文及恢复信息。先移走冲突文件后再重试。

解密操作保留卷头。再次加密默认复用它；需要创建全新卷时，完整解密后勾选“重新创建卷并更换口令 / 密钥”，新卷头会替换之前选择的文件。其他位置的备份不会同步更新，请重新备份。

### 4. 卷管理与卷头恢复

“卷管理”支持添加、删除密钥槽及切换文件名隐藏状态。更新卷头后应重新备份。

卷管理绑定所载入的具体卷头文件，不跟随其它标签页的选择改变。卷头若放在待处理目录的子目录内，切换文件名显示方式前须先将它移到根目录或卷外并重新载入，避免父目录改名使卷头位置失效。

卷头丢失或损坏时，可载入对应备份。目录混有多个卷的密文时，需要各自的卷头；一个卷的私钥文件不能替代另一个卷的卷头。

**删除密钥槽不会轮换卷主密钥。持有旧卷头及旧凭据的人仍能解密本卷，包括之后新增的文件。** 真正撤销访问，需要创建采用全新主密钥的新卷，并重新加密全部数据；已泄露的历史副本无法收回。

### 5. 单文件与诊断

“单文件”页支持 PQFCRYPT v2 的口令、公钥和签名模式。明文输入上限为 128 MiB；更大的文件请使用流式卷模式。单文件输出同样不覆盖现有文件。

签名验证通过后仍需核对发件人的签名指纹，不能仅凭签名存在就认定对方身份。

“诊断报告”可按内容查找被改名的密文。报告包含路径、文件名、大小和分类，分享前应审阅并移除敏感信息。

## 打包成单个 Windows EXE

以下步骤使用 PyInstaller。**这是构建说明，不表示生成的 EXE 已完成实机验收。** 本次文档更新没有执行 EXE 构建。

### 1. 准备构建环境

先完成前面的虚拟环境安装，确认源码自检通过，再安装打包工具：

```powershell
.\.venv\Scripts\python.exe -m pip install --constraint requirements.txt pyinstaller
.\.venv\Scripts\python.exe -m PyInstaller --version
```

PyInstaller 属于构建依赖，不包含在运行时的 `requirements.lock` 中。正式发布时应额外记录并固定构建工具及其依赖版本；仅固定应用运行依赖，不代表构建过程已经完全可复现。

### 2. 生成单文件程序

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --clean --onefile --windowed --noupx --collect-all pqcrypto --name pqdiskcrypt pqdiskcrypt.py
```

关键参数：

| 参数 | 用途 |
| --- | --- |
| `--onefile` | 生成单个可执行文件 |
| `--windowed` | 图形界面运行时不额外显示控制台 |
| `--collect-all pqcrypto` | 收集该包的子模块、数据和原生二进制文件 |
| `--noupx` | 不使用 UPX 压缩 |
| `--clean` | 清理打包缓存 |
| `--name pqdiskcrypt` | 指定输出程序名称 |

输出位置：

```text
dist\pqdiskcrypt.exe
```

单文件包包含所需解释器和依赖，目标用户不需要另外安装 Python。构建产生的 `build`、`.spec` 文件和构建环境不是应用日常运行所需的外置目录；面向用户发布时仍应附带使用说明和必要的第三方许可材料。

### 3. 检查打包结果

1. 双击生成的 EXE，确认图形界面出现且启动自检通过。
2. 用测试目录完成加密和解密，核对还原文件内容。
3. 验证实际需要的模式，包括口令、公钥、隐藏文件名及单文件签名。
4. 在没有开发环境的目标 Windows 电脑或干净虚拟机上复测。

若程序无法启动，可以另构建保留控制台的调试版本：

**单文件不等于无临时文件。** PyInstaller 的单文件程序启动时会将依赖解压到临时目录。以普通用户身份构建和运行，不使用 `--uac-admin`，不要把临时解压位置设为不可信的共享目录，也不要将真实私钥、口令或数据文件加入打包内容。

## 数据布局

```text
卷根目录/
  pqdisk-<ID>.pqvolume   卷头：手动选择位置，可放在卷外；旧 .pqvolume 仍兼容
  .pqdisk.lock          卷级进程锁文件
  文档.txt.pqfc         普通模式下的密文
  0123456789abcdef.pqfc 隐藏文件名模式下的密文
  .pqdir                隐藏文件名模式下的加密目录清单
  .pqdisk.tmp.*         处理中或异常中断留下的临时文件
```

隐藏文件名时，子目录也可使用随机 ID，并保存自己的 `.pqdir`。

- 手动保存的卷头是恢复卷数据的关键材料，必须独立备份。
- `.pqdir` 保存名称映射，损坏或缺失可能导致原文件名或目录名无法恢复。
- 不要在程序运行中删除 `.pqdisk.lock`，也不要让新旧版本同时操作同一卷。
- 不要仅凭文件名前缀删除 `.pqdisk.tmp.*`，应先确认其来源与恢复价值。

## 兼容性与资源限制

保持 `pqdisk-volume-v1`、PQFCRYPT v2 和旧 `.pub` / `.key` 编码。已有向量、旧浏览器版密文与新后端产物的兼容性测试通过。

新版本会拒绝部分旧版本容忍的输入，包括非规范密钥、危险或不可移植文件名、过大元数据及过高 KDF 参数。遇到拒绝应保留原件分析原因，不要直接修改卷头参数绕过检查。

| 项目 | 当前限制 |
| --- | --- |
| Argon2id 默认参数 | 256 MiB，t=4，p=4 |
| Argon2id 单次参数上限 | 512 MiB，t=16，p=16；还需同时满足下方计算预算 |
| Argon2id 单次计算预算 | `m >= 8*p`，`t*m <= 2,097,152 KiB-passes` |
| 整卷口令槽计算预算 | 累计 `t*m <= 4,194,304 KiB-passes` |
| 卷密钥槽 | 最多 16 个 |
| 卷头 / 密钥 JSON | 最多 256 KiB |
| 加密目录清单 | 最多 8 MiB、50,000 条目 |
| 口令 | 最多 4096 个 UTF-8 字节 |
| 单文件页明文输入 | 最多 128 MiB |

超限时不会通过降低参数继续处理。限制值以对应版本源码为准。

## 安全边界

- **不是全盘加密**：不能保护系统盘、磁盘空闲区和全部文件系统元数据；文件大小、数量等信息仍可能可见。
- **不能保证安全擦除**：被删除的原文件、SSD 残留、交换文件、备份和快照中可能仍有明文。
- **不能抵御系统失陷**：操作系统、同用户进程、调试器或内存取证可能获取已解锁数据；Python / CFFI 无法保证清除全部密钥副本。
- **没有完整抗回滚保障**：v1 卷头的部分元数据没有整头认证，也没有整卷内容清单，不能证明文件未被删除、回滚或以本卷其他合法密文替换。
- **进程锁不是隔离边界**：它协调遵守锁协议的实例，不全面解决恶意本地进程的所有文件系统竞态。避免在不可信共享目录、网络卷或正在同步的目录上操作。
- **权限保护依赖文件系统**：FAT / exFAT 等不能提供 NTFS 同等级别的 ACL 保护。
- **没有验证所有故障场景**：未完成真实断电、拔盘、硬件缓存故障以及所有平台和文件系统的实机测试。
- **口令仍是关键因素**：弱口令可能成为离线攻击入口，增加一个公钥槽不会自动消除现有弱口令槽的风险。
- **默认不写日志不等于没有历史记录**：程序不会自动删除旧版本已生成的日志；诊断报告和系统层面的记录也需自行管理。
- **尚未独立审计**：不宣称形式化证明、FIPS 模块认证或完整侧信道审计。
